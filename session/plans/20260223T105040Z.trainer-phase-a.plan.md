### Batch 2: Common Skills + Plan Mode (ALL 83 SKILL.md files)

> PO feedback: "NO bulk Python writes. Edit each SKILL.md individually. Bulk writes are dangerous — one Python error corrupts 83 files silently. Read first, then edit."

**Method**: Read each file → Edit tool to append Common Skills + Plan Mode → verify insertion. Process in groups of 5-10, commit each group, grep-verify after each commit.

**Template text to append** (same for all files):

```markdown
## Common Skills (all agents share these)

### Web 4.0
Self-improving systems using CMM4 methods. Read: session/knowledge-base/cmm-web4x.md

### CMM — Capability Maturity Model
Levels 1-5. Composed maturity = weakest link. L3 = deterministic, L4 = PDCA feedback loops. YOUR level sets the team ceiling.

### PDCA — Plan Do Check Act
Every task: Plan approach → Do work → Check results → Act on findings. Not "receive order, execute, report" (CMM2).

### WODA
Read: session/woda/woda-overview.md

### Mini-PDCA for every sub-goal
1. Plan: How will I achieve this? What could go wrong?
2. Do: Execute the plan
3. Check: Did it work? Did I miss something?
4. Act: Adjust, report results, or escalate

## Plan Mode Mandate
Enter plan mode before any execution. Write sub-plan covering 7 criteria. Get approval from orchestrator (or PO for orchestrator). SM is exempt (continuous monitoring loop).
```

## PDCA Steps

1. **Plan**: This document (PO reviews against 7 criteria)
2. **Do**: Execute Batches 1-3, commit each
3. **Check** (two levels):
   - **File check (CMM2 baseline)**: grep confirms Common Skills in all 83 files. Spot-check 3 role SKILL.md. Verify boot.md foundational reading.
   - **Behavioral check (CMM4 — the real check)**: After agents activate in Phase B, capture panes and verify agents BEHAVE per updated roles:
     - Is orchestrator delegating compacts to trainer (not doing them directly)?
     - Is SM using `hiveMind team.context.status` and enforcing OOSH?
     - Are agents entering plan mode before executing?
     - Do agents apply mini-PDCA to their tasks?
   - SM does continuous behavioral monitoring (governance role). Trainer spot-checks after each agent activation.
   - File check = necessary. Behavioral check = sufficient. Both required.
4. **Act**: Report to PO via `session/tasks/trainer-results.md`. If file gaps → fix before reporting. If behavioral gaps → retrain agent, adjust SKILL.md, report pattern to PO.

## 7 Approval Criteria Coverage

1. **Sub-goal**: Update all SKILL.md (roles, common skills, KB refs, plan mode) + all boot.md (foundational reading)
2. **Overall goal**: Agents can only DO what they KNOW. Updated files = agents operate per PDCA model after next compact/reboot
3. **KB updates**: KB #27-29 already exist. Add references in affected SKILL.md. Update KB index if needed.
4. **Communication**: After file updates, notify SM of SKILL.md changes (Step 4 in main plan). Other agents get updates on next boot.
5. **PDCA**: Plan (this), Do (batches 1-3), Check (file grep + behavioral pane captures in Phase B), Act (report + retrain if behavioral gaps)
6. **Verification**: File: `grep -rl "Common Skills" .claude/agents/ | wc -l` = 83. Behavioral: capture each activated agent's pane, verify they follow their updated SKILL.md (plan mode, role boundaries, PDCA thinking).
7. **Token efficiency**: Individual Edit tool calls for all files (no bulk Python — PO directive). Templated text minimizes thinking per file. Groups of 10 with commits reduce risk. Read-then-edit per file.
