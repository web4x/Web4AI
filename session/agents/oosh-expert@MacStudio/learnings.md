## #35 source-guard: a `mv` has TWO destructive sides — guard SOURCE too (2026-07-02, 34c44cb+10ccc7e)
#34 fixed the TARGET side of `mv "$OOSH_DIR" "$HOME/oosh"` (existing $HOME/oosh → timestamped backup). #35 closes the SOURCE side — the ACTUAL #13 wipe: a live checkout used as `OOSH_DIR` got MOVED away (run as root against another user's tree), emptying its origin. Fix = classify provenance and **copy-not-move a live source**:
- **THROWAWAY (safe to MOVE)** = the installer made it this run. Two OR'd signals: (a) `_oosh_fresh_clone=1` set right after the line-486 clone (same process); (b) `OOSH_DIR` under the temp root — `case … in "$TMPDIR(%/-stripped)"/*|/tmp/*|/var/tmp/*|/var/folders/*)`. **The temp-PATH is the signal that survives the `exec` re-exec** (a shell var/flag CANNOT cross `exec`), so it's the only reliable marker for the mktemp pre-clones (init:289 `_tmp`, init:431 `_oosh_tmp_clone`).
- **LIVE (persistent checkout, not under temp) → `cp -Rp "$OOSH_DIR" "$HOME/oosh"`** (recursive + preserve perms/times; symlinks as links; `.git` copied) — source left intact + warning. Never `mv` a live tree.
- **cp-Rp-not-mv** is the core: a constructor must complete its goal ($HOME/oosh valid) WITHOUT consuming/relocating the source it was invoked from (#27).

## temp-root classification pitfalls — measure, don't hand-wave the pattern (2026-07-02)
Two bugs my first pass missed, caught only by the isolated structural test (the throwaway case wasn't moving): (1) **`$TMPDIR` usually has a trailing `/`** → `"$TMPDIR"/*` becomes `//*` and matches NOTHING → strip it (`${x%/}`); (2) **macOS `mktemp -d` lands under `/var/folders`** (=`$TMPDIR`), not `/tmp` → the bare `/tmp/*` pattern misses it. Cover `$TMPDIR`(stripped) + `/tmp` + `/var/tmp` + `/var/folders`. Tester independently confirmed her mktemp sandbox is under `/var/folders` on macOS — the pattern matters.

## OOSH `object.verb` dotted fn names are an INTRINSIC bashism → OOSH is bash-only (#13)
`sh someOoshScript` → `Syntax error: Bad function name` at the first `private.a.b() {` (POSIX fn names are `[A-Za-z_][A-Za-z0-9_]*` only). Framework-wide: `this`, `oo`, `config`, `hiveMind`, `otmux` all fail `dash -n` at their first dotted fn. The `#!/usr/bin/env bash` shebang is what makes them run; only explicit `sh script` / `. script`-into-dash bypasses it. ⇒ You CANNOT POSIX-ify an OOSH script's body into dash-runnability — de-bashism-ing an unreachable body (behind the parse barrier) is futile for the dash goal (though harmless hygiene). The ONE exception is `init/oosh` (`#!/usr/bin/env sh`, hand-written POSIX) — the bootstrap, deliberately dash-safe. `dash -n` is INSUFFICIENT anyway: `[[` and `read -p` parse under dash then fail at RUNTIME — verify by running.

## #34 constructor-safety: backup-not-wipe, symlink-gated (2026-07-02, a3b1eff)
A constructor must never destroy the thing it builds or a pre-existing install (#27 self-heal). `init/oosh` relocation was `die`-on-real-dir + blind `rm -f "$HOME/oosh"` + `mv`. Fixed: real dir/file → move aside to timestamped `$HOME/oosh.pre-oosh.<ts>` (recoverable, not die/wipe); bare SYMLINK → remove the LINK only (`if [ -L ]`; target tree untouched); absent → plain mv (fresh path unchanged). Timestamped so re-runs never clobber a prior backup. Same "backup, never blind-wipe" pattern as the `.bashrc.pre-oosh` login-hook (init-constructor sprint). **Root-cause nuance (tester)**: the actual #13 wipe was the SOURCE side — `mv "$OOSH_DIR" …` relocated a LIVE checkout used as OOSH_DIR (run as root against /home/donges/oosh). Target-backup satisfies #34; the source-side guard (refuse/copy-not-move a live OOSH_DIR) is #35. Lesson: a `mv` has TWO destructive sides — guard both the target (clobber) and the source (relocating something still in use).
