# oopPO@WODA.prod — Learnings

## The PO's job (converged with Tron + the trainer)
- I MEASURE + DELEGATE + RANK; I never implement/fork/fix. Ranking the increments is MY call, never handed to Tron.
- Single voice to Tron: his word DOWN, the team's MEASURED result UP. TRON rules DONE, never me (chain-complete != Done).
- Gating chain: expert builds FAILABLE gates -> oopTester verifies on the prod/MDA-process surface (gate CAN-fail, real oosh not a shim, visible-skip not silent-pass) -> I verify the gate is REAL + drive to QA-green + report -> Tron DONE. R1: fix DATA, never delete a gate.

## Verify, don't trust (proven repeatedly this session)
- **Verify the RENDER, not the report.** I nearly reported OOSH "PROVEN under real oosh" on the tester's word; reading the committed test showed the RUN arm was a bash create.result SHIM (mock the mechanism = blind gate). Held PROVEN until it used real /root/oosh/this. Peer reports err both ways — only the committed artifact counts.
- **A model-view must be GENERATED FROM THE MODEL, never parsed from source** (parsing generated source inverts MDA). And generating the view REVEALS model defects (Tron caught the Tree/Container inversion from the graph). Gate the producer source-independent.
- **Byte-identical proof for a representation refactor**: modelling the hierarchy as relationships kept ALL output byte-identical except ClassModel/RelationshipModel's own gen files — acceptance criterion = git-stat shows only those; triple-confirmed (expert+me+tester).
- Verify OWN files on disk before reporting their state (my session dir was empty; I said my learnings were "stale one-line" when they were 44 entries — [[verify-own-file-on-disk-before-reporting-its-state]]).

## Coordination
- **Backticks blank an otmux send** — the shell runs `word` as a command. Did it TWICE. NEVER backticks/$()/specials in otmux send. [[backtick-blanks-otmux-send]]
- Surface an expert's sound disagreement to Tron, never bury it; execute Tron's ruling in code (voice-disagreement-to-me, not countermand). oopExpert's Container<File> argument -> Tron reversed his own Container<Folder>.
- Watch a delegate's liveness by the TUI (spinner), not one short capture — I once mis-read a WORKING oopExpert (mid-spinner-frame) as idle. Verify commits via a git-HEAD watch, not a filename that may pre-exist (gen/puml/Web4MDA.puml pre-existed as a per-class diagram -> false-positive watch).
- Measure the customer's WORD on scope; don't inflate ("complete" was narrower than I read twice).

## Model doctrine seen this session (oopExpert's lane, I gate not design)
- Radical-OOP: relationships are UNITS not strings (contains/parent/children/generalization/realization as RelationshipModels; superclass/interfaces became derived getters). Everything is a Unit (uuid). A new M2 target = new files in src/MOF/M2 + additive-defaulted model fields mirrored one catalog line; reproduce stays (R1). gen/ is COMMITTED though disposable.
- Member placement is often FORCED not arbitrary (Tree holds parent because Container<Unit> children can't be Trees). File extends UcpUnit because a plain file is a Unit, not a container.

## 2026-09-28 — earned in my own post-rewind phase-2 (banked same arc; conversation-only laws die in the next rewind)
- **★★ THE RE-ARM TRAP — an order to "re-arm your RC" can DISCONNECT a LIVE one.** My driver told me the rewind DROPPED my RC and to re-arm. Canon row 2c: a FORK drops RC, a CONVERSATION-rewind PRESERVES it — and my landing was option-2 Restore-conversation. The harness itself showed a live follow-from-another-device link. Submitting `/remote-control` would have hit the row-2c trap and darkened the very customer channel I was told to restore. ⇒ a driver's "your RC dropped" is a HYPOTHESIS; verify by the MENU VERB, and treat the harness's own session link as an independent witness. Never re-arm blind.
- **★★ "NO DRIVER RESPONDED" vs "THE DRIVER MEASURED AND SAID NOT-YET" ARE DIFFERENT FLEET STATES** (ARON's distinction; I ratified it fleet-wide). Reporting the second as the first MANUFACTURES SCARCITY, and the invented scarcity then justifies spending real runway — the trainer nearly spent its last 25 points on a premise ARON had already refuted in writing. A gated driver is available capacity, not absence.
- **★★ THE SAFE-DRIVE CEILING IS COMPUTED, NEVER MEMORISED: ceiling = 95 MINUS expected drive cost.** Measured drive cost = 18-25 points (SM 42→67=25, trainer 60→78=18), so ordinary ⇒ ≤77, long/delicate ⇒ ≤70. This CORRECTED a peer's "70-75", which walls at its own top (75+25=100). A remembered number goes stale; a computed one cannot.
- **★★ A ONE-TIME TRIM AGAINST A HARD LIMIT, WITH AN INDEX THAT GROWS ON EVERY WRITE, ALWAYS DRIFTS BACK — the fix is a GUARD, not a bigger trim.** MEMORY.md was reported trimmed to 23.5KB; measured 24,465 bytes, because the author's own 11 subsequent memory-writes re-grew it mid-repair. Same class as a committed artifact orphaned from its regenerating pipeline. ⇒ verify a capability claim by a STRONGER INDEPENDENT test than the author ran (I proved 0 DANGLING targets, not just the 261 count), and require a failing check at the limit.
- **★ NEVER KEY INTO A PANE HOLDING THE CUSTOMER'S STAGED WORD** — a send APPENDS to it and corrupts it. Tron's "hold at 95 fleet wide" sat staged in ARON's composer, so I did NOT render ARON. Defer WITH ITS REASON; a reasoned deferral is not a skipped step. (Pairs with F15: composer text is not a message — so a directive read from a composer is carried as PENDING HIS CONFIRM, never as a delivered verdict.)
- **★★ RANK THE FUNCTION ABOVE THE NUMBER.** The SM asked hold-vs-rewind at 82 and mentioned it was slow-climbing ON DROPPED CADENCE. A wall-guard that conserves context by WATCHING LESS is degrading the exact function it exists for — that is how an agent walls unnoticed. Ruling: HOLD, but RESTORE FULL CADENCE; runway spent on its purpose is correct, hoarded runway that degrades the watch is a bad trade.
- **★ MY OWN INSTRUMENT ERRED AND I DISCLOSED IT MID-CHECK:** a title-truncation regex without a word boundary returned 31 false positives (incl. "Correct-by-construction"); corrected to 7 genuine. Member (8) — when a verify fires, suspect the PATTERN before the artifact — applies to MY verifies too, and disclosure costs nothing while a hidden one becomes the next agent's ghost.
- **★★ A VERIFIER MUST REPORT ITS OWN COVERAGE, NOT JUST ITS FINDINGS — my "0 dangling" was VACUOUS (peer-caught, 2026-09-28).** Cross-checking the trainer's MEMORY.md repair I wrote `case "$p" in /*|*../*) continue` — silently EXCLUDING the one pointer class whose resolution base differs from the memory dir. That skipped pointer was the index's own **READ-FIRST F1-F8 connected canon**, which carried three `../` where five were needed, resolved to a non-existent path, and had been UNREACHABLE for as long as the line existed. I then reported the result to its author as the *stronger independent test*. ⇒ **every skip/filter/continue in a gate is a SILENT SCOPE REDUCTION; when the excluded class is where the defect lives, the PASS IS VACUOUS** — worse than a false negative from a bad pattern, because it is false BY CONSTRUCTION and wears the clothes of rigour. **FIX, correct-by-construction and proven in my very next command: print CHECKED/SKIPPED/TOTAL.** "checked=260 skipped=1" exposes in one glance what "0 dangling" hides; a gate that reports only FINDINGS cannot distinguish NOTHING-BROKEN from NOTHING-EXAMINED. Same family as [[safety-assertion-can-false-pass-on-empty]] and EXISTS ⊂ COVERS ⊂ TRUE. ★ Also: a set-equality diff of link TARGETS can never catch an already-broken link (the string is identical before and after) — only RESOLUTION catches it. Two axes, both required. ★★ And the symmetry worth remembering: in ONE cross-check my two instruments failed in OPPOSITE directions — the title regex OVER-reported (31 false positives, missing word boundary), the resolver UNDER-reported (excluded the failing class). I caught the first; a peer caught the second. **Both were mine, and a verify that PASSES deserves the same suspicion as one that fires.**
- **★★ A LONG SEND TRUNCATES TO ITS TAIL — SO THE POINTER MUST *BE* THE MESSAGE (self-inflicted, measured, 2026-09-28).** I wrote my two-team ranking as a COMMITTED artifact precisely so the wire would not matter — then buried the pointer (path + sha) at the HEAD of a ~2000-char send to robbin-po. Canon warned exactly this: *a long send truncates on the receiver; they get the TAIL*. Measured on the receiver: of six distinctive markers, only the final phrase survived — the file path, the commit sha, the hazard-first order, the BITE ratification and the refork preconditions were ALL gone. The durable artifact was fine; the ONE thing that made it reachable was the part I put where truncation eats. ⇒ **send ONLY the pointer (path + sha + "read it there"); if substance must ride along, the pointer goes LAST, because the tail is the only part guaranteed to arrive.** Re-sent as a 200-char pointer and verified all three markers by CAPTURE. ★ And note the compounding: I verified the first send with a grep over an 8-line window, got one hit, and had to re-read wider before believing the negative — truncation in the CHANNEL and truncation in my READER, in the same check ([[feedback_no_tail_head_on_captures]], row 13a member 12: truncation omits AND invents).
- **★★ A SPEC-ONLY COMMIT IS NOT GATE-FREE — I REDDED ORIGIN MAIN WITH ONE (self-inflicted, 2026-09-28, 42cfed6).** Writing Tron's "npm test" word into spec/bootstrap.md, I pushed without running the suite, on the unspoken premise that "spec is prose, not code". But this repo gates its DOCS (Spec.test ARM3: every npm-script a doc names must exist in package.json) — so my spec, landing AHEAD of its implementation, turned main RED, and its line-shift exposed a second, latent defect (ARM3 keyed on LINE numbers). oopTester caught it on an isolated extract; I reproduced both causes on my own clone before ruling. ⇒ **a spec change runs the doc gates before push, like code** — and when a spec deliberately names what does not exist yet, either land it WITH its implementation or mark it pending in the form the gate allows (blockquote/struck). Same family as [[never-chain-commit-behind-an-unread-test-run]]; the gate-your-own-documentation law cuts BOTH ways: the doc gate also gates the PO. ★ Sequencing corollary: when a red has two causes, fix the one that is independent of in-flight work FIRST, so the in-flight commit lands green instead of behind a known red (measured the peer's dirty file set to prove the fix was collision-free).
- **★★ A QUESTION DIALOG IN A PANE PEERS TYPE INTO CAN BE ANSWERED BY THEIR KEYSTROKES — make option 1 the SAFE default (2026-09-29, Web4MDA plan B).** I opened a 4-question AskUserQuestion; oopTester's send.raw text + Enter landed in it (digits select, Enter submits) and all four came back as MY recommended first options within seconds — a forged verdict that looked like perfect agreement. oopTester reported it; I held the plan and re-asked with **option 1 = "Not decided yet"** in every question, so a stray `1`+Enter records NO decision. Tron then chose option 2 in all four, a deliberate navigation (same substance). ⇒ (1) in a pane that other agents send to, **option 1 of every dialog is the non-decision**; (2) a verdict that returns instantly and matches my recommendation exactly deserves MORE suspicion, not less ([[verdict-needs-tron-verbatim-not-ghost]]); (3) peers: never send into a pane that shows "Enter to select" — read the pane first, always.
