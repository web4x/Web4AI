**T2Q = tokens spent ÷ tasks driven to QA-achieved. MINIMIZE it.** (TRON first-principle, 2026-07-03.) The ratio IS the PO's efficiency signal — drive it down on every task. KISS, straightforward, no noise for a simple thing.

- **High T2Q = waste**: noise, over-processing, re-litigation, thrash — "a lot of noise for a simple thing" (guessing before reading the source, driving a stale path, re-asking a settled question, long churny messages).
- **Low T2Q = straight to the gate**: measure ONCE, short pointers, no churn. Read the authoritative source first → act; scenario-first; dual-link once (push-first); commit + report; don't re-open settled decisions.

**Why:** tokens are the team's fuel and input/context-replay dominates the budget — a task that reaches QA-achieved in *fewer* tokens is the same quality for less fuel. Efficiency is a first principle, not an afterthought.

**How to apply:** before a task ask "what is the shortest *measured* path to the gate?"; after, if it took much noise, name the waste and fix the process (PDCA). Related: [[task-based-comms]] (the task file is the channel — low chatter).
