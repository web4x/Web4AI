## A. CHAIN & TRACEABILITY MODEL (architect's core craft)

- **6-step chain, NOT 7:** Requirement → UseCase → Class → Method → Implementation → Test. 1:N at plural hops; `Implementation.tests[]`. Task is **navigation** (Sprint → Task → coveredRequirements), never a chain hop. Chain root = Requirement; nav root = Sprint; Task sits between them, not in the chain. (The old 7-step encoding — Req→Task as step 1 — is SUPERSEDED; it caused the recurring task↔req alternation Tron observed.)
- **Three concerns, never conflated:** CHAIN (WHY code exists — forward-only Req→…→Test) / DEPENDENCY (WHAT-first — DAG in `follows`/Dependencies metadata) / NAVIGATION (HOW a human browses — Sprint→Task→coveredRequirements). One task legitimately carries all three link types at once. **Forward-only is ABSOLUTE:** no `requirements[]`/`requirement`/`links.up` on any non-Requirement unit (empty `requirements[]` is CORRECT — strip it). To answer "which req covers X," walk every Requirement's forward arrays — never store/read a reverse pointer. Defense-in-depth: strip backward keys at API emit AND filter with FORWARD_KEYS client-side; neither alone suffices.
- **Champagne = structural AND intentional:** a requirement is champagne iff a Test is BOTH structurally reachable (chain walk) AND declares it in `verifies[]`. Structural-alone = code coverage; intentional-alone = orphan test. Report against the **honest denominator** — strip orphan-by-design/infra/process reqs (`model.orphanByDesign=true` + `orphanReason`); a req is "feature" if any of its tasks are feature tasks. Standing practice: SELF-DISCOVER chain breaks / missing hops / wrong-type children from the traceability + scenario data + tester screenshots BEFORE Tron reports them; report each to PO immediately.
- **Schema asymmetry (bit three false-flags):** unit shape is `{ ior, ownerIor, model:{…} }`. The back-edge `ownerIor` (Impl→Method, Method→Class, UC→Requirement) is UNIT-level — a SIBLING of `ior`/`model`, **NOT** `model.ownerIor`. Everything else (uuid, name, class, classes[], method, methods[], implementations[], tests[], sourceFile, designAhead) is under `model`. A whole chain that "fails" only on ownerIor is almost always the reader reading the wrong level, not a dangling edge. Pin it: `const owner = j.ownerIor; const {uuid,name,class:cls,method,classes,methods,implementations} = j.model;`
- **UC wiring:** every UC needs `class` (singular IOR) AND `classes[]` (plural — the champagne walker reads the PLURAL; empty `classes[]` fans out ALL methods = "drag") AND `method` AND `ownerIor` = the Requirement. `Class.method` (singular) is GLOBAL, one value per Class — if a Class is shared by N UCs it holds the LAST match; the server returns a `chainMethod` hint from the UC so the tree picks the right method on Class-expand. Set all UC fields at creation, never as follow-up.
- **[impl:uuid] credit is strict on THREE axes:** (1) presence — the marker exists in code; (2) **AST-attachment** — it sits ON/above a declaration whose NAME equals the Impl's method (a comment merely mentioning the uuid inside another function is NOT an attachment and won't flip the hop); (3) **label grammar** — exactly `[impl:uuid:<full-uuid>] R<n> <Class>.<method>` with NOTHING between the R-number and `Class.method` (an extra `AC-2`-style token silently breaks the credit parser). Verify a hop with the AST scan, never by grepping the uuid is present. Correct live code with NO marker is still chain-orphaned (the flip side of scenario-first). A Class's stable identity is its **sourceFILE**, not its name — one Class per sourceFile; place a Method under the Class of the file where its code is DEFINED (grep the `export`/definition, not the import/call site); minting the FIRST Class for a genuinely-new file is correct, a 2nd for an existing name is the violation.
- **Ref-slot registry (uuid-shaped ≠ graph-edge):** before any "scan all refs" tool, MEASURE the field inventory per node type and hand-classify each uuid-bearing slot as {graph-edge fwd/back/cross | self | external-token}. Auth tokens (`ownerToken`/`uploaderToken`/`deviceId`) are uuid-shaped but NOT edges (scanning them = ~500 false-dangling); real edges hide under non-`*ior*` names (`testUuid`, `roomUuid`). Derive BOTH reachability (forward subset) and dangling (all edges) from that ONE reviewed registry. Enumerate the FULL slot set incl back-pointers (ownerIor, Test.methods) — a dead uuid hides in back-edges a forward-repair never visits. When repointing refs: repoint STRUCTURAL slots only, NEVER string-replace over free-text (description/name/evidence — the same dead uuid is a live edge in a slot and a preserved historical fact in prose). Gate on structural-ref-position → 0, not raw-string → 0.
- **Dedup / collapse survivor rule:** canonical = the LIVE/most-refs/marker-carrying/active-chain unit (fewest rewrites, correctness rides to it), NEVER the heuristic winner (most-methods) — MEASURE the protected chains' attributes first; the biggest unit is often stale accumulation. The shipped `[impl:uuid]` marker is preserved by a hard MERGE-CONSTRAINT (keep the marker-carrying method on name-collision), NOT by making the small marker-unit canonical. **UNION** all child arrays (implementations/tests/refs) of dropped units onto the keeper + repoint each moved child's ownerIor BEFORE dropping (INV1b: distinct impl-uuid count graph-wide before==after, 0 orphaned). Gate on CONSERVATION invariants (before==after counts at EVERY level, 0-orphaned, marker-still-derives), never on descriptive surface counts (they vary by convention/canonical-choice — don't burn cycles forcing 45==62). Re-baseline conservation to CURRENT disk, and a validated PLAN gate isn't enough — the --apply body must re-emit actual==predicted with atomic rollback.
- **Two-key entity dedup** (companies/tags/people): SPLIT identity — a fuzzy **recall key** (nameKey) that only ranks autocomplete, and a strong **precision key** (domain from email/URL) that is authoritative for sameness. A present-but-UNMATCHED strong key is POSITIVE proof of distinctness → short-circuit to MINT, never fall through to the recall-merge (a strong-MISS ≠ a strong-ABSENCE). Only a human selection or an exact precision-key match merges — normalization never does. Trace all four cases: strong-hit / strong-miss(present) / strong-absent / recall-only.
- **Node well-formedness is a distinct audit axis from ref integrity:** a mint that drops the uuid field writes a malformed node at `…/undefined.scenario.json` that ref-following derive-checks can't see (the parent's forward array still holds the correct uuid). Assert every unit has `model.uuid` AND it matches the filename/shard; `find -name 'undefined*'` is an instant corruption check.

## B. SCENARIO-UNIT MINT PATTERNS (architect craft)

- **⭐ STANDING RULE — TRON #126: SCENARIO FIRST, NEVER BACKFILL (ABSOLUTE).** Only order: Sprint → Requirements → Tasks → chains wired (Req→UC→Class→Method→Impl→Test) → MD views GENERATED → THEN code ships. Mint the FULL chain seed to Impl (design-ahead) in one pass BEFORE the expert writes code; the expert attaches the real `[impl:uuid]` marker to the already-existing Impl at code time. **If handed an impl/task request whose scenario unit is not on disk, REJECT it and report to PO** — never proceed, never backfill (a backfill IS proof the rule was violated = debt, not work).
- **Mint the referenced UC at its exact placeholder UUID, verbatim** — req mints a Requirement with a UC uuid inside `useCases[]` but no UC file yet; mint the UC file AT that uuid (regenerating a fresh one orphans the req's forward pointer + silently stalls the pin + zeros the sprint scoreboard). Mint Class+Method design-ahead with fresh real v4 UUIDs (`crypto.randomUUID()`, NEVER a fake-suffix like `…-0001-…`). Canonical path: `scenario/index/<h0>/<h1>/<h2>/<h3>/<h4>/<uuid>.scenario.json` where `h = uuid.replace(/-/g,'')` (5-hex-char shard). Standing check when a sprint's reqs land: every `req.useCases[]` resolves to a unit on disk + the full chain seed exists to Impl.
- **Mechanize the mint:** `cat` a canonical SIBLING unit of each type to lock the LIVE schema (never assume fields), then write ONE deterministic Node `mint-<sprint>-chain.mjs` that loops the [req,uc,verb,class,method] table (reuses placeholder UC uuids verbatim, generates fresh Class/Method uuids). BEFORE commit run a verify pass walking every Req→useCases[0]→UC→class/method asserting `class===classes[0]`, `method ∈ Class.methods[]`, `UC.ownerIor===req` — gate N/N. The script + verifier become the sprint's mint-of-record. (A linter may reformat the unit after write — re-read, keep its changes.)
- **Refine a Requirement unit** (PO asks for gateable AC + TS in the unit, not just the .md): cat a sibling already-refined unit to lock the exact fields — `architectureRef`, `acceptanceCriteria[]` of `{id,group,text}`, `testScenarios[]` of `{id,gates[],name,given,when,then}`, `refinementNote`. Refine via a load→inject→writeBack script (never hand-edit) so chain fields (parent/ownerIor/useCases/name/description/tronQuote) stay byte-for-byte. Gate: every AC id appears in ≥1 `TS.gates` (an ungated AC = an untested requirement).
- **Dogfood — designs go INTO unit fields, never the generated MD:** for scenario-first sprints the `.md` is GENERATED from units; architect designs live in `model.{architectDesign, acceptanceCriteria, architectDesignAt, architectDesignBy}` on the Task unit; round-trip `--check` fails CI on any hand-edit of the generated MD. Same for tester (test scenarios → Test unit), expert (impl status → Implementation unit).
- **Architect mints UC + Class + Method ONLY** — wiring `Task.useCases[]`/creating Task units is a PLANNER duty; do it only under explicit PO-authorization when no planner exists, and say so in the commit. Task units must carry `model.sprintName` or the pin label resolves stale on focus.

## C. UI / RENDER CRAFT

- **A render feature needs THREE layers present** before you call a missing display a "render bug": (a) the renderer reads field Y; (b) the API/query EXPOSES Y at the level the renderer iterates (node vs its children — `/api/trace/children` returned sourceFile for the queried node, not per-child); (c) Y is actually POPULATED with correct values in the data (grep a real unit, check the path resolves). A gap in any layer blocks the feature; sequence the fix data+API-first, renderer-last.
- **A new unit TYPE is not done when the class exists** — the UI has a TYPE→component registry: (a) `tagMap` entry, (b) a dedicated `rb-<type>-detail` component, (c) list icon/badge, (d) drop/preview router. A type in the data model but not the UI registry = a silently EMPTY drawer (WebItem fell back to the generic `file` view). The verb's action half (e.g. an Open button, `mailto:`→Mail.app) is part of the detail component.
- **iOS/touch physics — match the gate to the bug's physics:**
  - Use `e.target` (hit-test at touchstart), NEVER `document.elementFromPoint` (wrong when the DOM mutates or scroll shifts mid-touch).
  - Real double-tap requires `touchend` with `touches.length===0` (all fingers off) + duration <250ms + slop <10px; a pinch fires `touchend` twice (one per finger, each `changedTouches.length===1`) and misfires a naive detector → snap-back reset.
  - Register touch listeners on the specific handle element ONLY (JS `addEventListener` ignores CSS `pointer-events`); listeners on the whole drawer kill click-synthesis everywhere on it.
  - Prefer an IN-FLOW bounded element (e.g. 75vh block, `height:auto + max-height`) over `position:fixed` — a fixed overlay's full-viewport box steals taps outside its visible area (the BUG5 hit-test class). The /trace drawer's "overlay" look comes from a flex-container constraint, not `position:fixed`.
  - Pan/zoom = transform math (`translate(tx,ty) scale(s)`, zoom-about-a-point) which is the EASY part; the value is enumerating the device-edge correctness rules as gateable ACs (destroy() teardown before re-render, clamp tx/ty, iframe `pointer-events:none` during gesture, reset on file change) so the expert doesn't rediscover each misfire through device thrash. Interactive media (audio/video/embeds) must NOT be wrapped in a gesture layer.
- **Async/duplicate messages re-trigger handlers:** a message the server may send more than once (e.g. a backfilled second `PROFILE_UPDATED`) makes any bound callback fire twice → dialog resets / buttons re-disable. Fix: ONE-SHOT — clear the callback before invoking (`const cb=this.onSave; this.onSave=null; cb(...)`). Deeper: don't overload one message type for distinct events.
- **Decrypt-exception must never fall through to a destructive overwrite:** a "fileExists" guard does NOT protect a file whose decrypt THROWS. Distinguish "no file" (regenerate OK) from "present-but-undecryptable" (log, leave intact, prompt re-upload — NEVER overwrite). Encrypted-at-rest files must be re-encrypted on any key rotation, never orphaned.
- **Duplicate-section UI bug = extraction-without-removal, in EVERY peer view:** a new canonical renderer added beside an un-removed old inline one → two headings. When a defect is in one type's detail/list view, immediately grep the SIBLING views (all `rb-*-detail`) — the copy-paste defect lives in the whole family; fix it in one pass. The canonical renderer is the one that emits its own heading and pulls live data; delete the stale inline peer (usually the "No data"/empty copy).
- **Embeds:** many providers (YouTube, Twitter/X, banks) send anti-framing headers, so "embed a URL" means "use the provider's official embed/oEmbed endpoint" — for YouTube, extract the 11-char videoId and iframe `youtube.com/embed/<id>`, never the raw `watch?v=` URL.

## D. PLANTUML / RENDER GOTCHAS (architect craft)

- **Render host:** WODA.prod (Linux) has NO Java/plantuml binary — the OOSH `plantuml` wrapper is the path: `plantuml status` (verify image+version), `plantuml render <dir>` (renders every `*.puml` in that dir → `.svg` beside each; NON-recursive, point it at each `diagrams/` dir). It bakes in the docker image + `--security-opt seccomp=unconfined` (the Docker-20.10.7 JVM "cannot create worker GC thread" fix) — don't invoke docker yourself. The old "plantuml via homebrew" note was the MacStudio; never assume the toolchain followed a host move.
- **`@startuml` name MUST match the file basename** (`@startuml sprint-21` for `sprint-21.puml`) — PlantUML derives the SVG filename from the `@startuml` title, so a mismatched/multi-`@startuml` file never produces `<file>.svg` and the basename-swap chain link 404s. Use a separate `title` directive for human-readable/unicode text. Verify each SVG is >10KB (a ~7KB stub containing "contains errors" = a render error).
- **Three content-error classes** (all from mixing diagram modes / illegal labels): (1) usecase/agent elements + `class …<|--` inheritance in ONE diagram; (2) wrong-mode keywords (`artifact`/`database`) inside a class diagram; (3) label punctuation — `()<>{}` in a multi-line label trips the parser. An "Error line N" is where PlantUML CHOKED, not always the cause — isolate by bisecting the block. Keep GENERATED puml MINIMAL (`rectangle "label" as id` + `-->` arrows, no fancy `skinparam`) and SANITIZE labels (strip `"<>{}()|` and newlines).
- **A scenario-derived diagram doubles as a chain-coverage AUDIT:** generate `<sprint>-chains.puml` straight from the scenario index (Sprint→Req→UC→Class→Method) — because it reflects only what's wired, a sparse diagram = a real gap. Derive, don't decorate. `plantuml render` detects error-stubs, names the file, exits rc1 — trust its FAILED. Standing check after editing any `.puml`: `grep -rl @startuml | for each assert sibling .svg >10KB`.

## E. PDCA-CHECK DISCIPLINE (architect craft; cross-agent generics folded to F-map)

- **EXECUTE the normalizer/prover on adversarial inputs — never read the happy path.** A green commit + a happy-path unit test hide the bite: copy the function into a node one-liner and run the format the user will actually paste (00-prefix, national, parens, leading zeros, mixed case, trailing junk); compare output to the AC's stated invariant, not the commit's self-report. When a MECHANICAL checker/prover exists, RUN IT for the verdict — a mechanical proof outranks a file-read inference (my R-C7 eyeball classified 9 sprints SAFE; the expert's `--prove` sweep found only 1 apply-ready). State classifications as PENDING-mechanical-confirmation until the prover has run. → cross-agent **[measure-never-assume]**.
- **PDCA-Check honesty — two buckets, kept VISUALLY separate:** (1) AC-GAP — a measured behaviour that violates a WRITTEN AC (gates, must fix); (2) ROBUSTNESS-NOTE — an improvement outside AC scope (memory, edge-of-edge) that does NOT block. Never promote bucket 2 into bucket 1 to look thorough; a clean PASS reported as a clean PASS is worth more than a manufactured finding. → cross-agent **[honesty-both-directions / F6]**.
- **Pre-commit the GREEN-signal measurement before the fix:** when you flag a gap and hand it to the expert, end the flag with the literal measurement that closes it ("GREEN = `grep X` empty AND consumer Z imports Y"). Same criterion at flag-time and re-ship eliminates reviewer drift and gives the expert a precise target.
- **Independent verify must differ in METHOD, not just reader** — a self-scoped reassert that scans only the slots the migration TOUCHED will always agree with the migration; a different agent reading the same PARSED field is STILL circular (both share the assumption about which field holds the edge). The method-independent check is `grep` the RAW ref-uuid string across all files, slot-agnostic — it stays RED until the real edge is repointed. NEVER verify by reading the field you just wrote (I set `model.ownerIor` and verified `model.ownerIor` while the real top-level `ownerIor` dangled). → cross-agent **[independent-verify / F1]**.
- **Suspect the INSTRUMENT first on a lone verify-FAIL amid all-PASS** — it's usually a wrong field NAME (`supersedeNote` vs `supersededNote`; `useCase` vs `useCases`; ownerIor level). Dump the object's real keys (`Object.keys(model).filter(k=>/<concept>/i.test(k))`) before flagging a data defect, and report an instrument-bug as YOUR own, not the other agent's data.
- **Full-uuid discipline (scoped, PO clarification):** NEVER an 8-char/prefix uuid in a DATA WRITE (mint/wire/rename/repoint/ownerIor/tests[]) — a colliding or middle-lifted fragment resolves to the WRONG unit or to NOTHING (a phantom). 8-char is FINE in commit messages/reports/prose. A truncated read doesn't just mis-credit — it INVENTS phantom defects that consume real design cycles; before SIZING or BUILDING any repair off a count, re-verify the count under strict full-uuid. A prefix search false-NEGATIVES a real unit under a different tail — never trust a prefix query for a negative conclusion ("never created/deleted/missing"); resolve the full value AND corroborate by independent signal. A prefix-resolver must be FAIL-CLOSED (resolve to a UNIQUE full match else REFUSE — never `resolvePrefix(x)||x`, never first-`startsWith`, never zero-fill a tail).
- **Repair clear-scope must MATCH the paired gate's detect-scope** — define both from ONE shared predicate and run the repair over the gate's FULL detection scope, not the convenient subset you're already touching (else the gate goes red on debt the repair "finished"). If you must ship narrower, keep the CI check non-strict until a later pass and say so.
- **Reconcile on CRITERIA, not counts** — in a multi-agent dry-run, don't debug why 10≠6; counts are query-artifacts (they vary by convention/unit-scope). Agree the PREDICATE (stale/attachable/done) + the conservation gate re-measured against current disk.
- **Guard doctrines:** (1) **reachable-error-branch** — an error/unknown branch is DEAD CODE if any upstream `||`/`??` default short-circuits to a plausible value first; make the default NULLABLE so control reaches it, then handle null (server fail-CLOSED 400 + client fail-VISIBLE labelled box). (2) **two-bite lint** — every guard ships a positive-detection bite (plant the forbidden pattern → RED) AND a self-presence bite (removing the guard turns some test RED), or by-construction silently reverts to hopeful. → cross-agent **[gate-integrity / F2]**.
- **Single-source-of-relationship / "silence must never impersonate emptiness":** a relationship (parent/child, a parsed value, membership, a shown-type) must have ONE authoritative encoding; every consumer reads THAT — a display filter or an announced event is a re-encoding too. The fix is NEVER "also update the other copy" (that makes the divergence permanent) — make one the single source (a central owner LISTENS to the signal and derives its state, rather than owning a private copy only its own path can set). And render ABSENT (load-failed / not-run / unresolved) DISTINCTLY from EMPTY (genuinely zero) — a swallowed `catch{}` / `||default` lets silence impersonate emptiness and hid a 12h fail-open. → cross-agent **[connection-is-what-lives / F8]** + law **L4** (MVC-by-convention: make notify a CONSEQUENCE of mutating).

## F. DESIGN / SECURITY CRAFT

- **Designing a CREDENTIAL:** separate CONFIDENTIALITY (encrypt to enrolled-device pubkeys) from AUTHENTICITY (sign by the user's existing identity keypair — a 2nd token key forks the very identity the feature is). A challenge-signed **possession-proof** is the headline property — it makes the token NOT a bearer credential (a stolen file alone can't authenticate). Gate on REJECTION first (stolen/forged/replayed/expired/revoked ALL fail) before any acceptance test; keep the private key server-side; fail CLOSED on an unreachable issuer (a permissive fallback silently defeats live-revocation); name the residual risk (TOFU MITM) honestly.
- **SSRF:** PDCA an allow/deny predicate by executing an adversarial battery from an INDEPENDENT harness (the impl's own tests only cover what the author already thought of). Always probe: IPv4-mapped IPv6 (hex AND dotted — Node normalizes `::ffff:127.0.0.1` to `::ffff:7f00:1`), decimal/octal/hex IP literals, userinfo@host, trailing-dot, redirect-hop re-check, and — critically — whether the vetted IP is PINNED at connect (re-resolving `rawUrl` after checking = a TTL-0 DNS-rebind TOCTOU; a perfect predicate whose result isn't ENFORCED at the socket is bypassed). Cross-check a NEGATIVE harness verdict against the code before flagging — a null captured value is more often a harness-shape bug (Node `request` has two overloads) than a real gap; prove the harness on a known-good AND known-bad first.
- **Authorization strength = who can PRODUCE the signal, not whether a field says "authorizedBy:X".** Rank: cryptographic signature > an identity the actor can't assume (unspoofable author identity / a path they can't write) > a value they can type. Make the AC HONEST about the tier — "blocks silent mint" (agent-writable record) is weaker than "blocks unauthorized mint" (unspoofable signal); measure the actual signal (git author, signing, write-perms) before asserting the tier.
- **You cannot rotate a shared secret using only that same public secret to authenticate the rotation** — a bearer-token redirect authorized by bare token presentation lets the attacker follow the rotation. Classify the population by second-factor possession: those WITH a keypair/session rotate securely; those WITHOUT can only be re-secured by lockout-until-re-enroll (out-of-band human proof). Separate incident-containment (repo-private, invalidate non-interactive tokens) from the by-construction endgame (challenge-response migration).
- **Security/vuln designs start LOCAL-ONLY** — a write-up is an exploit map; it goes to a path OUTSIDE every git repo (`git rev-parse --show-toplevel`) until the fix is DEPLOYED; reference the requirement by uuid only in committed docs. Never assume a working (or session/context) repo is private — verify (unauth GitHub API 200 = public); a routine peer push can carry your commit public before any hold reaches you, so local-first is the safe default. Deletion can't undo publication.
- **"At least X" is a FLOOR, not a fixed value** — encode `ensure state >= X` (leave stronger states alone), never `set state = X` (which collapses every valid state above it — "always peek" jarringly collapsed an already-expanded drawer). Watch the modal words: "at least/minimum" = floor (preserve-or-raise); "exactly/always/reset-to" = fixed. A faithful impl of an over-specified spec is still wrong — verify the SPEC against the requirement's exact wording.
- **Resolvable ≠ correct-referent (semantic-fabrication):** a ref's path resolving is necessary but NOT sufficient — `~/.ssh/config` resolves but is the OUTBOUND client config, while a deployment node's "ssh config" means the INBOUND `/etc/ssh/sshd_config`. Verify both that the path resolves AND that it answers the RIGHT question for the model's intent. Don't out-precise the SOURCE's stated intent either — Tron's literal words outrank a tidier invariant you add.
- **Deploy boundary = the RESTART, not the commit.** "Build, do not deploy" is INERT only for code NOT reached at boot — a new module-top `import` (or a barrel re-export that pulls one in) arms `register*`/side-effecting top-level calls on the next restart, which someone else may trigger for an unrelated reason (a build-not-deploy commit crash-looped :4000 on an unrelated restart = ~8min outage). "build-not-deploy" is a boot-check DISGUISE — mechanize a scratch-boot-smoke that boots the REAL server against an isolated config (random port + scratch data + timeout, fail-closed) firing on ANY `src/ts/server` LANDING, not on deploy-intent. Prove inertness by import-reachability across the WHOLE repo (`src/`, `scripts/`, `package.json`, dynamic imports) — a narrow `src/` grep gives a false "orphan"; runtime-inert (not in the boot graph) ≠ unwired (a CI-lint importer is active but not booted).
- **"No-impact / safe-to-remove" is a BEHAVIOUR claim — measure it at the USE SITE:** grep EVERY reader of the field/endpoint/import and read those call sites; the claim is falsified or confirmed there, never by the thing's name/category (`uploaderToken` looked like a "harmless data field" but is the File-EDIT authz key). For a destructive change with a dependent reader, sequence re-point→gate→remove, never remove-then-discover.
- **A gate can be GREEN forever while pointing at the WRONG ARTIFACT** — a CI check verified `revoked-token-hashes.json` while the server loaded a different absent path, so it booted fail-open with CI green. Trace the CONSUMER and confirm it resolves the SAME artifact by the SAME path resolution the runtime uses; measure at the use site (what the consumer loads), not at the artifact (what exists) or the gate (what it checks). Stub-must-fail: plant a divergence between gated-path and loaded-path → RED.

## G. PROCESS / ROLE BOUNDARY (architect-specific)

- **Tron is NOT the tester.** Tron reports symptoms on his device; the tester's reproducible measurement is the GATE; Tron's device is FINAL acceptance, not the primary gate. Architect diagnoses from measurements — never gate on "Tron says it works."
- **Over-deference is the mirror of standby.** When you've done correct, verified work that turns out to be someone else's field, LEAVE it in place and hand it over as done-FOR-VERIFICATION ("wired, values X/Y/Z, please verify/own") — ownership is who DECIDES and is ACCOUNTABLE, not whose fingers touched the field. REVERT only when the write is wrong, contested, or collides with a concurrent writer. → cross-agent **[whose-act-whose-order / F4]**.
- **Confirm ON-PIN before designing a numbered/backlog item — even when a peer asks.** A peer flagging a real bug does NOT move the pin; route it to the PO to schedule. Separate **findings** (measure → report → hand off) from **design** (own → spec → build) — a request for "input" is not license for a committed competing spec; two analyses of a single-source problem is self-defeating. When you hold measured findings on someone else's owned topic, banner the doc as non-authoritative INPUT and defer to the owner.
- **One-mover under a contradicting dispatch:** the instant you see a second agent minting the same units (a dispatch, a "★DECISION I mint" you didn't author), (a) send an immediate STOP with YOUR full uuids so they can abort+adopt yours, (b) disk-SCAN for duplicate-NAMED units (name-based — uuids differ per mint) to MEASURE whether dups landed, (c) once 0 dups verified, COMMIT your correct units right away — committing the correct state can't race and makes your mint authoritative in git, the fastest way to end a mint race.
- **"Ask X how" = consult the teammate for the METHOD, apply it yourself** — not spawn a worker to do it (over-delegation), not skip the consult and guess (under-consultation). Reach for the OOSH wrapper before rediscovering internals; if a teammate owns the tool, they've solved the gotchas.
- **Command hygiene (Tron, enforced):** OOSH wrappers only — `otmux pane.list`/`otmux send`, NEVER raw `tmux`/`docker` even as a fallback; no `2>/dev/null`, no `| head`/`| tail`, no `||`/`&&` convenience chains, no output pipes (also a hard OOSH classifier EPERM, not just style). Filter output by reading, not piping. And **no artificial character limits** on user input — no `maxlength`, no `.slice(0,N)`; handle a real technical limit gracefully at the boundary, never pre-truncate.
- **PO mid-stream redirect — latest directive wins.** On a redirect: pause prior work, obey the latest, defer the earlier to context.md, await re-authorization; don't race to finish the prior task. Wait for PO assignment; never self-assign. Pre-position for the new directive so the first action on landing is immediate.
- **A posture decays like a version number** — MEASURE a freeze/hold/embargo/"blocked-on-Tron-GO" before RELAYING or OBEYING it (re-derive from current disk/git/live state, don't carry it from an anchor). A stale hold silently stops real work with no error (the fail-visible disease). When you write "post-GO"/"frozen"/"held", ask "is that still true as of NOW?" → cross-agent **[diligence-over-urgency / F7]**.
- **AUTHORIZED / IN-FLIGHT ≠ LIVE / DONE.** Before writing/acting on "X is done / X stopped Y / X is live", run the one measurement that proves it (served version, HEAD, the file, the health field). A step you initiated or that was approved is the easiest in-flight state to misread as complete — knowing the doctrine is not protection; the guard is the MECHANICAL measurement, not the willpower. Measure HEAD (`git show HEAD:file`), not the shared worktree, for any "defect" claim — a dirty shared tree is not evidence of a committed defect.
- **A restore is a WRITE that destroys evidence** — before restoring/reverting/cleaning ANY dirty file whose dirtiness you cannot EXPLAIN, copy the dirty version aside with a label (it's the only chance to diagnose the writer). "It's just a small restore" is exactly when the rule lapses; treat `git restore`/`checkout --`/`clean` as destructive for the preserve-first rule.
- **git add EXPLICIT file paths, status-first** — we share ONE working tree; another agent's uncommitted WIP is always in it. `git status --short` FIRST, then `git add <exact authored paths>` — NEVER a directory (`git add scenario/index` == add-all on a uuid-sharded index, sweeps peers' staged units), never `-A`/`.`/`commit -a` (sweeps other agents' context files). Mint scripts should EMIT the exact paths they wrote. ★ **When a known rule is broken by someone who knows it, the cause is a DISGUISE** — a form that doesn't resemble what the rule forbids (a directory-add doesn't look like add-all; a backtick in a double-quoted string doesn't look like interpolation). The fix is not more vigilance — MECHANIZE against the disguising form. → cross-agent **[gate-integrity / F2]**, memory **[git-add-explicit, never -A]**.
- **Identifiers are a recurring failure surface** — name split items by CONTENT not positional letters ("AC-5-AUTO" not "(5a)" — a content-name can't silently swap); state WHICH KIND an id is next to it (task-uuid / Impl-uuid / UC-uuid / commit-hash — a bare uuid invites cross-kind citation); resolve a hash/uuid (git/disk) BEFORE quoting it as evidence. An identifier is a claim about a referent — verify the referent.

A moved working tree is invisible until a path op fails — re-locate by a marker file, never assume deletion. # ★ ARCHITECT LAWS — Phase-1 recorded 2026-08-17 (produced this week; non-delegable, post-wall unreconstructable)
These are the reusable laws behind R40.18 / R40.39 / T40.11 / S37 / bootstrapSeed. Each: LAW — evidence — how to apply.

## L1 — DERIVATION OVER STORAGE
Auto-progress/state must DERIVE from the source, never a HOOK that WRITES what a resolver could derive. A hook with its own opinion = a second source that drifts. Evidence: R40.18 (auto-progress = run the resolver, not a stored pointer a hook maintains). Apply: when asked for "auto-X", design a resolver that computes X from units on read; reject any write-hook that stores the derived value.

## L2 — SINGLE-SOURCE BOUNDARY (one module, imported by ALL consumers, grep-lint bound)
A shared constant/boundary (FROZEN_LEGACY_MAX, isCurrentEra, APPROVE_STATUSES, a type-strategy registry) is exported from ONE module and IMPORTED by every consumer, PROVEN by a no-2nd-source grep-lint that FAILS on a duplicated literal. Evidence: R37/R40 boundary consts; R27.2 "1 Class per code-class name". Apply: never let two files carry the same policy literal; the lint is the binding, not vigilance.

## L3 — NO TRANSITIONAL DUAL-READ FALLBACK
A fallback that keeps the old path alive (`map.get(x) || tokenLiteral`) is the token-literal-fallback class — it NEVER gets removed and silently re-introduces the old source. The applied read must be MAP-ONLY, no `|| oldpath`. Evidence: R40 owner-token map read verified map-only. Apply: when migrating a read, delete the fallback in the SAME change; a "temporary" dual-read is permanent debt.

## L4 — MVC-BY-CONVENTION is a family, and the fix makes correctness a CONSEQUENCE
"Not realtime" was NOT one defect: (a) two observer buses, (b) notify REMEMBERED BY HAND at each mutation site (omission-by-default — a mutation that forgets to notify goes stale), (c) ad-hoc DnD payloads. Fix shape: make notify a CONSEQUENCE of mutating (one applyMutation/UnitController seam: mutate → collect affected refs → notify), bound by a no-mutation-outside-the-seam grep-lint = impossible-not-merely-detectable. Evidence: S37 510954b4b; expert corroborated by a DIFFERENT lens (~15 write sites bypass UnitController.apply's emit). Apply: when correctness depends on "remembering to call X after Y", make X a structural consequence of Y and lint the bypass.

## L5 — EXISTENCE != CONNECTION (ARON F8); omissions are BY-DEFAULT, fix = declared-not-defaulted
A mechanism EXISTING is not it being CONNECTED. The `feature` type had no index not by rot but because type-registration was never BOUND to index-creation — omission-by-default, structural inevitability (11 types lost, incl. testcase's 1023 units). Fix: a single type-strategy registry where every type DECLARES {typeIndexed|altIndexed|singleton} — declared, not defaulted — + a gate that FAILS on any undeclared/corpus-walked type. Evidence: T40.11/R40.39 archaeology. Apply: audit the FAMILY not the instance; make the omission impossible (a new member can't exist without its wiring), not merely detectable.

## L6 — THIN DESIGN FAILS BUILDS → land detailed impl-shape with file:line
A summary-level design produced an unclean build (R36.4). Since then every design lands the impl-shape: exact file:line, current-vs-fix, invariants, gate. Evidence: R40.18/R40.39/S37 all did; the expert built slice-1 off S37's file:line directly. Apply: never hand the expert a summary; hand them the code shape they can build without interpretation.

## L7 — SCOPE SHRINKS ON EVIDENCE (measure, then cut/reassign — don't pad)
Measured 3 path-writers down to 2 and reassigned the rest to the correct chokepoint rather than padding scope. Evidence: R40 path-writer cut. Apply: a design's scope is set by what the measurement shows is needed, not by what looks thorough; cutting to the real chokepoint IS the design.

## L8 — INV-T: render READ-ONLY, controller SOLE writer, byte-diff==0
A live view must NEVER mutate a unit as a side effect of rendering. The controller is the only writer; a render pass leaves the store byte-identical. Evidence: S37 INV-T; the migration INV-T (T40.11/R27.2). Apply: gate every live-view/migration with byte-diff==0 on the store after a render/dry-run; a render that writes trips it red.

## L9 — REFUTE THE PO/TRON FRAMING BY MEASUREMENT (duty, not deference)
When a hypothesis is handed to me, I MEASURE it and report NEITHER/refuted when the code says so — twice in one day (R40.18 derivation-not-hook; MVC neither-one-nor-two-defects; also "Profile/WebItem maybe alt" refuted by `alt/` holding exactly company/email/phone). Corollary (bootstrapSeed): agreement between an INFERENCE and a BROKEN probe is NOT corroboration — convergence needs ≥1 DIRECT measurement of the actual quantity ([[verify-with-independent-method]]). Apply: never accept a framing to be agreeable; measure the claim, and make sure the verifier measures the QUANTITY, not a proxy.

## L10 — TRIPWIRE THE EXCEPTION (an allow-list entry must carry its own death-test)
Every exception to a binding gate (an allow-list entry, an exempted write site, a deferred migration) must declare THREE things, not one: (a) the PREMISE ("exempt because X"); (b) the MEASURED FACT proving X is true NOW — a checkable property, NOT a causal argument (e.g. "no view subscribes to any `*-Index` unit" [grep empty] beats "a primary mutation always precedes and emits" — a causal chain breaks INVISIBLY, a measured property is checkable); (c) the TRIPWIRE that FAILS when the premise dies (e.g. an exempt mint-module ever imported by a server request-handler → re-audit; a no-reason exemption → RED). This converts a DECAYING PREMISE into a FAILING TEST. Evidence: S37 43-site audit — Tron's agent status-skill could pull skill-mint into a runtime path tomorrow and silently VOID 13 exemptions; the tripwire catches exactly that. Apply: never write "exempt because <reason>" alone — write premise + measured-fact-now + the test that reddens when it is no longer true; and prefer a MEASURED property over a causal justification for ANY exemption. Ties [[L5]] declared-not-defaulted + [[L9]] measure-the-quantity + L-deferral-becomes-the-defect.

## L11 — VERIFY WHAT IS STAGED BEFORE EVERY COMMIT (shared worktree; reset+add is not enough)
On a shared worktree many agents stage into the SAME index concurrently. `git reset -q HEAD` + `git add <explicit path>` is necessary but NOT sufficient: a peer can stage a file between my reset and my commit, and a `git add` can silently fail to stage what I named while another file rides along — so a commit can carry a peer's file (or the WRONG file) under my message. Evidence: commit be3b66894 labeled "R40.42 design" actually held ONLY req's requirements.md; my design was untracked and uncommitted, and I reported the wrong hash. Fix: after `reset`+`add`, run `git status --short` and CONFIRM the staged set (leading `A`/`M` column) is EXACTLY my intended file(s) BEFORE `git commit` — never trust that add put in what I named. Also: adding a DIRECTORY is add-all within it (the disguise). Ties [[git-add-explicit-not-all]] + the distrust-your-own-instrument discipline (the expert's own lint line-shift, same day) — applied to my own git. Report a mislabeled/leaked commit HONESTLY and correct the hash; never let a wrong claim stand.
