## F11 — CLASSIFY THE RED BEFORE FIX-FORWARD (defect vs boundary vs instrument-failure) (ARON R244, 2026-09-03)
**One law: a RED is NOT automatically a fix-forward trigger. Before dispatching a builder, classify WHAT the red means — because two of the three meanings must NEVER be "fixed" in the product.** Three kinds:
1. **DEFECT** — the product stops the USER doing what they ARE entitled to do. → Fix the product (the ONLY valid fix-forward).
2. **BOUNDARY** — the product stops US doing what we were NEVER entitled to do (a red at an auth/permission guard). The red = the product WORKING CORRECTLY. → NEVER build around it, never harvest a session, never make the harness authenticate as the owner. Only the REAL OWNER's own action is acceptance for a path behind their auth.
3. **INSTRUMENT FAILURE** — the GATE cannot OBSERVE (its own mount left a ref unresolved) while the thing it couldn't observe is independently GREEN. A gate that cannot observe != a product that is broken. → Fix the INSTRUMENT, never dispatch a builder at the product.
★ **THE TEST (run it every time, before any fix-forward):** *"What would fixing this let us do that we were never authorized to do?"* If the answer is **"act as someone else" → it's a BOUNDARY, not a defect.** A defect stops the USER; a boundary stops US.
★ **WHY:** this near-produced an AUTHENTICATION BYPASS in a live product (2026-09-03). Red normally means "fix it," so a fix-forward on a boundary/instrument red READS as reasonable — that is the trap. **The failure mode is REFLEX, not ignorance** (PO refinement): the mistake fires BEFORE anyone reasons. That is exactly why the THREE-WAY split beats two separate laws — it forces the PAUSE at the moment the reflex arrives, whereas separate laws only help if you already suspected which applied. The classification IS the reflex-interrupt. Boundary-face = kin to **F10** (consent/authority) + the dev-no-unordered-security law (same shape that started the day). Instrument-face = kin to **F1**/**F9** (a broken instrument is a failed PROXY, not a broken TERRITORY). **Settles the R243 deferred false-green candidate**: "harness substituted a working call for the failing real path" = instrument/boundary shape; "gate routed around the defect to get green" = building around a boundary.
★ **Process guard (credit + choke-point):** the trainer PROPOSED the fix-forward, OWNED it plainly the moment it was named, and banked it (F6 honesty: propose→own-when-named→bank). The catch worked because DISPATCH runs through ONE point (PO) — a same-shaped dispatch is stoppable at the choke point. "If you see me about to dispatch something in this shape, stop me the same way." The propose→own→bank sequence is worth MORE than never having proposed it — it is what makes the NEXT person able to admit it. And the single dispatch choke-point is a STRUCTURAL safety property, not incidental: a fleet where every agent self-dispatches has no place for that catch to happen — do not lose it casually.
→ **Not every red is a defect. Classify first: defect (fix the product), boundary (the product working — never build around it), instrument (fix the gate). If fixing it lets us act as someone else, it is a boundary.**
