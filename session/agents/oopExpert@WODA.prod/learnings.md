## 2026-09-14 — RADICAL OOP in TypeScript, corrected by Tron on my FIRST file (learn it — I wrote the violation myself)
- ★ **FILE = CLASS NAME.** `src/index.ts` is a functional-era convention; a radical-OOP file is named after the class it holds: `src/Web4MDA.ts` holds `class Web4MDA`. Same for the test: `Web4MDA.test.ts`. (OOSH: the script file IS the class — `config` holds `config.*`.) My scaffold shipped `index.ts` — that was a violation the moment it was written, however green.
- ★ **NO ROGUE CODE BELOW THE CLASS.** Module-level `if (import.meta.url === …) { console.log(…) }` is functional machinery nobody owns. It belongs on the class as **`static start()`** — the OOSH `script.start()` constructor-of-the-process pattern. The class starts itself; the module's only top-level statement is `Web4MDA.start();`.
- **Make `start()` testable**: inject `argv` and `entry` with defaults (`process.argv`, `import.meta.url`), compare via `pathToFileURL(argv[1]).href` (not string-concat `file://`), return a boolean → 2 failable tests (imported = no-op; entry = runs). Green: typecheck/build/start/dev/3 tests, `017a8e3` pushed.
- **The trigger to watch for in myself**: any code I write outside a class body (free function, top-level `if`, helper) — stop, name the owning class, put it there as a method (static if process-level). Tron: "take the rogue functional code below the class into a static class start method. learn that!"
- ★ **EVERY CLASS MUST HAVE AN EMPTY PARAMETERLESS CONSTRUCTOR (Tron, 2026-09-14).** `new X()` always succeeds and yields a valid empty instance; state comes AFTER via `init(...)` returning `this` or `static from(unit)` = `new X().init(...)`. No ctor params, no parameter-properties, no ctor DI. Why: the scenario unit is the model → rehydrate-from-unit must be the ONE way to build (ctor args would be a competing second way = DRY violation); generic construction by name (`new (ctor)()`) for factories/registries/the traceability graph; an empty instance is the self-healing starting point. Write `constructor() {}` explicitly so a later "just one parameter" shows in the diff. Gate: `X.length === 0` per exported class. My spec's own `Room` example had `constructor(readonly id: string)` — I wrote the violation into the spec before the rule landed; Web4MDA spec §3 + `eb6046b`.
- ★ **EVERY CLASS: `private model: Model = {}` + `private isInitialized = false` + `init(model): this` (Tron, 2026-09-14).** `Model` is an ABSTRACT class with NO required members — that is precisely what makes the empty JSON `{}` a legal empty Model (TS structural typing). Each concrete class pairs with `XModel extends Model` carrying the typed fields; `init()` assigns the model, flips `isInitialized`, returns `this`; behaviour narrows with `this.model instanceof XModel` and answers honestly when uninitialized (`'Web4MDA (uninitialized)'`). `start()` = `new X().init().describe()`. Data moved OUT of the class fields INTO the model — the class owns behaviour, the model owns data, the unit IS the model. Web4MDA spec §3 + `595e126`. Gate: `X.length===0`, `model` equals `{}` before init, `init()` returns same instance + `initialized` true.
- ★ **A boolean getter is named `isX`, never `x` (Tron, 2026-09-14: "the getter returns boolean. so it must be called isInitialized!"). The private attribute is the plain noun: `private initialized = false`, `get isInitialized(): boolean` (Tron: "the attribute can be named initialized").** I had it backwards (`get initialized()` over `private isInitialized`), then over-engineered the fix with a `#isInitialized` sigil — unnecessary: attribute = noun (`initialized`), getter = predicate (`isInitialized`). General rule: name the public surface by its meaning (`isInitialized`, `hasChildren`, `canRender`); the private state is the noun it reads.
