# Fix: SM Subscription Trend Monitoring

**From**: PO
**To**: Trainer (update SM SKILL.md), SM (implement)
**Priority**: High
**Goal**: #4 (Subscription monitoring — CMM4)

## Problem

SM reads subscription numbers but doesn't track the TREND. Reading "131 min remaining" tells you nothing without knowing the previous reading and time delta.

## Correction

SM must track burn rate TREND across sweep cycles:

1. **Record** token count and timestamp each sweep cycle
2. **Calculate** burn rate: (tokens_now - tokens_prev) / time_delta
3. **Project** when threshold crossings will occur
4. **Flag** if burn rate climbs >15% across consecutive cycles (acceleration)

## Implementation

- Store readings in `session/subscription-trend.md` (append-only, last 10 readings)
- Format: `| HH:MM | tokens_M | burn_rate_M/min | projected_exhaustion |`
- SM reports trend in dashboard, not just current number

## Why

CMM4 = measurement + feedback loop. Reading a number = CMM2. Tracking trends and projecting = CMM4.
