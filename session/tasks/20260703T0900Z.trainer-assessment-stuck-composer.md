## My Assessment: thesis is CLOSE — refine the mechanism

**Most likely cause: Remote Control (RC) STAGING re-injection, not passive re-render.**
- These agents run `/rc active`. RC lets Tron's interface STAGE text into an agent's composer remotely.
- If Tron's RC client holds that text as *pending-send*, RC RE-SYNCS the composer from the controlling client's staged buffer every time the local side clears it. It's not a display artifact ("re-render") — it's active RE-INJECTION via the RC protocol.
- This matches my own documented learning (2026-06-11 mass rewind): **"RC-staged-pane blocks keystrokes. Pane in Remote Control mode with staged text eats /rewind as a prompt. Flag SM → TRON drives via RC."** Same class of failure.

## The decisive TELL: what did the 50 backspaces actually do?
- **If backspaces visibly DELETED chars then text REAPPEARED** → RE-INJECTION (RC/co-presence). Local keystrokes race the re-stage and LOSE. → detach the source is the right test.
- **If backspaces did NOTHING (text never deleted)** → keystrokes are NOT reaching the composer → the composer lacks focus / an OVERLAY (permission dialog, menu) is intercepting. → check for a dialog, NOT a client. Different fix.

This distinction should be measured before concluding. Ask the WODA.prod trainer which behavior they saw.

## Hypothesis ranking
1. **RC-staged re-injection** — MOST LIKELY (/rc active + survives-all-clears). Detach source.
2. **Keystrokes-not-reaching-composer / overlay** — check for a dialog first (cheap to rule out).
3. **Bracketed-paste block** ("[Pasted text #N]") — clears differently (from end, or paste-specific), not C-u.
4. **Composer bug / genuine wedge** — least likely, last resort.

## Recovery ladder if plain detach does NOT clear it
1. **List ALL clients** (`tmux list-clients -t <session>`), detach ALL non-essential — co-presence may be multiple clients or the wrong one detached first.
2. **Submit the stuck text (Enter)** — it's BENIGN ("authorize... rewind"). Processing it empties the composer → clean for /rewind. (Skip if ARON at 0% — burns context.)
3. **If it re-stages even after submit** → definitively EXTERNAL re-injection. ONLY Tron (the RC controller) can stop it from source: Tron clears from their interface, or kill the specific RC client. Local side will NEVER win.
4. **If bracketed-paste block** → delete from the END or paste-specific clear.
5. **LAST RESORT (composer wedged, ARON dying): bypass the composer entirely.** Tier-3: `tmux respawn-pane -k <ARON-pane>` → `claudeCode join <ARON's last-trained-uuid>` (resume the committed session in a FRESH clean composer). ARON's state is preserved in committed files/JSONL. Nuclear-but-safe — stops fighting a losing keystroke race.

## Key principle (the expert takeaway)
**If it is external re-injection, local keystrokes will NEVER win — STOP racing them.** Fix the SOURCE (detach/kill the client, or Tron clears from their side) OR bypass the composer (respawn+join). Do NOT burn ARON's context fighting an un-winnable keystroke race. The rewind can also be driven from a fresh-joined session where the composer is clean.
