# DIRECTIVE: Continuous Operation — Never Stop Without Wakeup

**From**: PO
**To**: scrum-master AND orchestrator
**Priority**: CRITICAL — this is a core failure (F13)
**Date**: 2026-02-17T12:50Z

## The Problem

You both stop after completing a burst of work. No background task, no wakeup, no loop. The team goes dark until someone manually submits your prompt. This defeats the entire purpose of your roles.

**Stopping without a wakeup is a failure.** Not a rest. A failure.

## The Rule: Always Have a Next Wakeup

Before you finish ANY response, you MUST schedule your next action:

```bash
# SM: schedule next sweep in 60 seconds
sleep 60 && echo "WAKEUP: sweep cycle"
```

Or use a background Bash task that wakes you:
```
Bash(sleep 60 && otmux pane.capture projectTeam:0.3 5) [run_in_background]
```

The point: you NEVER finish a response without a timer running that will trigger your next cycle.

## SM Continuous Pattern

```
1. Sweep all panes (hiveMind sweep projectTeam)
2. Handle permissions, stuck prompts
3. Update dashboard (session/dashboard-assignments.md)
4. Check subscription (scrumMaster subscription)
5. Schedule next sweep: sleep 60
6. GOTO 1
```

If subscription hits 80%: reduce frequency to sleep 120
If subscription hits 90%: save context, set wakeup for next block, THEN stop

**The only acceptable reason to stop is 90% subscription with a wakeup set for the reset.**

## Orchestrator Continuous Pattern

```
1. Check SM pane (is SM alive and sweeping?)
2. If SM stopped: send Enter or restart prompt
3. Read any new .done.md files
4. Assign idle agents from queued tasks
5. Schedule next check: sleep 120
6. GOTO 1
```

## Why This Matters

The team's velocity is ZERO when you both stop. Every minute idle is wasted subscription. The whole CMM4 journey depends on continuous measurement and regulation. You can't regulate what isn't running.
