# Task: Fix claudeCode script to launch with 256 color + UTF-8 by default

**From**: developer (projectTeam:1.3)
**To**: oosh-expert (via PO approval)
**Priority**: MEDIUM
**Date**: 2026-02-20T10:23Z

## Problem

When launching Claude Code via the `claudeCode` oosh script inside a tmux pane, it starts in black-and-white mode without UTF-8 support. Users have to manually set 5 environment variables before launching, which defeats the purpose of having a wrapper script.

## Root Cause

The `claudeCode` script does not ensure the following environment variables are set before launching the claude binary:

| Variable | Required Value | Why |
|----------|---------------|-----|
| `TERM` | `xterm-256color` | Tells the app the terminal supports 256 colors |
| `COLORTERM` | `truecolor` | Enables 24-bit RGB color output |
| `LANG` | `en_US.UTF-8` | Enables UTF-8 character rendering (box drawing, etc.) |
| `LC_ALL` | `en_US.UTF-8` | Overrides all locale categories to UTF-8 |
| `CLAUDECODE` | *(must be unset)* | Claude Code refuses to start if this is set (anti-nesting guard) |

Additionally, tmux itself needs these settings (already applied to `~/.tmux.conf` but worth noting):
- `terminal-features` must include `256:RGB` for xterm
- `terminal-overrides` must include `,xterm-256color:Tc`

## What to Fix

The `claudeCode` script at `/Users/donges/oosh/claudeCode` should:

1. **Before launching claude**, ensure the 4 env vars are exported:
   ```bash
   export TERM="${TERM:-xterm-256color}"
   export COLORTERM="${COLORTERM:-truecolor}"
   export LANG="${LANG:-en_US.UTF-8}"
   export LC_ALL="${LC_ALL:-en_US.UTF-8}"
   ```
   Use `${VAR:-default}` so existing values aren't overwritten if already correct.

2. **Unset CLAUDECODE** if it's set (to allow launching from within a tmux session that was started by another Claude Code instance):
   ```bash
   unset CLAUDECODE
   ```

3. The claude binary is at `/Users/donges/.local/bin/claude`. The script should either use the full path or ensure `~/.local/bin` is on PATH.

## What NOT to Change

- Do NOT modify `otmux.tree()` or `otmux.tree.detailed()`
- Do NOT change the existing `claudeCode session.id` or `claudeCode session.name` methods — they work fine
- Only change the launch/start method(s) that actually invoke the claude binary

## How to Verify

1. Open a fresh tmux pane (e.g., `ooshDebug:0.0`) with a plain bash shell
2. Run `claudeCode` (or whatever the launch method is)
3. Claude Code should start with full color output and UTF-8 box-drawing characters
4. No manual `export` commands should be needed

## Reference

The working manual command sequence (what the script should automate):
```bash
unset CLAUDECODE && export TERM=xterm-256color COLORTERM=truecolor LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 && /Users/donges/.local/bin/claude
```
