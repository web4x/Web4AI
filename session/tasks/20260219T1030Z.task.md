# PO Directive: SM Boot Quality — Prevent Post-Compact Degradation

**Priority**: HIGH — this is the team's weakest link
**From**: PO
**To**: Orchestrator → delegate to expert (boot file) + trainer (SKILL.md)
**Goal**: G3 (Team self-management) + G4 (Subscription monitoring)

## Problem

After every compact, SM loses its operational identity. The auto-generated boot.md is 22 lines of generic template. SM's learnings.md has 93 lines of hard-won patterns but boot says "read ONLY if needed." Result: SM falls back to primitive behavior — calls `subscription` in a loop, doesn't use hiveMind sweep, forgets duties. This is CMM1 for SM recovery.

## Root Causes

1. Auto-generated boot.md has NO role-specific operational loop
2. Learnings.md not loaded — boot says "only if needed"
3. Context.md goes stale (last updated hours ago)
4. No inline rules in boot — SM must read 3+ files to reconstruct identity

## Required Fix

### Task 1: Expert — Create curated SM boot file

Create `session/agents/scrum-master/boot-curated.md` that REPLACES the auto-generated boot on every SM reboot. Must contain:

```markdown
# ScrumMaster Boot

You are scrum-master on projectTeam:0.3.

## Your Loop (run immediately, no setup needed)

1. `hiveMind sweep projectTeam` — capture ALL panes
2. Unblock permissions: `for agent in orchestrator oosh-expert oosh-tester agent-trainer task-agent woda-writer woda-scribe developer script-product-owner; do hiveMind unblock "$agent"; done`
3. `scrumMaster subscription` — check burn rate TREND (not just current value)
4. Write dashboard: `session/dashboard-assignments.md`
5. `sleep 60` — then GOTO 1

## 5 Rules (non-negotiable)

1. hiveMind tools ONLY — no raw tmux, no manual bash loops
2. NEVER touch pane 0.4 — skip in ALL operations
3. Capture 30+ lines before judging any agent's state
4. Never stop without scheduling next wakeup
5. Max 15 min per response — yield and restart loop

## MANDATORY: Read learnings

Read `session/agents/scrum-master/learnings.md` NOW. It has your institutional memory. Do NOT skip this.

## Context

Read `session/agents/scrum-master/context.md` for team state snapshot (may be stale — verify with fresh sweep).
```

The expert should also update the PreCompact hook (`/Users/Shared/Workspaces/AI/Claude/.claude/hooks/pre-compress.sh`) to generate this curated content instead of the generic template for scrum-master role.

### Task 2: Trainer — Update SM SKILL.md

Add to SM SKILL.md:
- "Boot Recovery" section: ALWAYS read learnings.md first. Not "if needed" — ALWAYS.
- "Anti-patterns after compact" section: calling subscription in a loop without sweeping, forgetting hiveMind tools, marathon responses
- "The Loop" section: sweep → unblock → dashboard → subscription trend → sleep 60 → repeat

### Task 3: Orchestrator — Verify after next compact

After next SM compact, orchestrator must:
1. Send curated boot file (not auto-generated)
2. Wait 2 minutes
3. Capture SM pane (30+ lines)
4. Verify: is SM using hiveMind sweep? Is it in the loop?
5. If degraded: flag to PO, iterate on boot content

## Success Criteria

- SM reboots into productive loop within 2 minutes of compact
- SM uses hiveMind sweep (not manual captures)
- SM reads learnings.md on every boot
- SM maintains 60s sweep cadence
- This pattern survives 3 consecutive compacts without degradation
