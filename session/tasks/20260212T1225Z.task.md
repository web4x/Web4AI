## Problem

hiveMind stores its role registry in `/tmp/hivemind.roles`. That's volatile — dies on reboot. This violates the OOSH config pattern.

Current (WRONG):
```
/tmp/hivemind.roles  ← volatile, plain text, no config script integration
```

## The OOSH Config Pattern (web4 scenario)

OOSH already has a defined pattern for persistent configuration:

```
~/config/                          ← CONFIG_PATH
├── user.env                       ← main config, sources others
├── oosh.env                       ← OOSH-specific vars
├── log.env                        ← logging config
├── stateMachines/                 ← state machine persistence
│   └── SETUP_SERVER.states.env    ← state as env file
└── hivemind.roles.env             ← WHERE REGISTRY SHOULD LIVE
```

These `.env` files are **web4.scenario.env files** — the OOSH pattern for persistent shell configuration. They:
- Use `export VAR="value"` format
- Are sourceable: `. ~/config/hivemind.roles.env`
- Persist across reboots
- Integrate with `config set/get/save/list`
- Are the DEFINED way to store state in OOSH (CMM3)

## What to Implement

### 1. Move hiveMind registry to config pattern
- Create `~/config/hivemind.roles.env` with proper `export` format
- `hiveMind role.register` writes to config, not /tmp/
- `hiveMind role.resolve` reads from config, not /tmp/
- Keep backward compatibility: if old /tmp/ file exists, migrate it

### 2. Use `config` script methods
- `config save hivemind` to persist
- `config list hivemind` to inspect
- `config get HIVEMIND_ROLE_<pane>` to query

### 3. Any other /tmp/ usage in OOSH
- Audit all scripts for /tmp/ usage
- Each one should migrate to the config pattern
