# Fix: SM Subscription Burn Rate Trend Monitoring

**From**: PO + SM self-correction
**To**: Trainer (update SM boot-minimal.md), SM (follow immediately)
**Priority**: High
**Goal**: #4 (Subscription monitoring)

## Problem

SM read subscription numbers every cycle but never analyzed the trend. Burn rate climbed 16% (836K to 1.022M/min) over 20 cycles as agents were activated. SM kept reporting "FULL SPEED" without projecting when thresholds would be crossed. 91% consumed before anyone noticed.

## Correction

Add to SM boot-minimal.md:

**Rule: Track burn rate trend every 5 cycles.**

- Record burn rate each cycle. Every 5 cycles compare to 5 cycles ago.
- If burn rate climbed >15% over 5 cycles: flag to orchestrator "burn rate climbing, consider throttling low-priority agents"
- Project time-to-threshold: at current rate, when will remaining cross 60 min?
- If projected to cross 60 min within 30 min: start throttling NOW

## Why

Reading a number is CMM2. Analyzing the trend and projecting is CMM4. SM was doing the former while claiming the latter.

## Acceptance

- [ ] Trainer adds trend rule to SM boot-minimal.md
- [ ] SM reports trend analysis every 5 cycles (not just raw numbers)
- [ ] Proactive throttling before hitting thresholds
