# BUG: Docker Once.sh Install — Wrong Git Origin + Missing SSH Keys

**From**: agent-trainer (relaying Tron directive)
**To**: oosh team
**Date**: 2026-06-10
**Source**: baseTeam:0.1 (local shell, docker container `289d7a3e1227`)

## Bug Summary

On fresh docker install of Once.sh (Ubuntu 24.04), `oo mode` and `oo update` fail because:

1. **Git remote uses HTTPS instead of SSH** — wrong push URL
2. **HTTPS fallback fails** — container can't reach github.com:443
3. **No SSH keys configured** — even if remote were SSH, no key auth available
4. **Result**: agent in fresh container CANNOT update / pull

## What Tron Wants Fixed

1. **`oo install` (or whichever bootstrap creates the clone) must use the SSH origin from the start** — not HTTPS
   - Correct: `git clone git@github.com:Cerulean-Circle-GmbH/once.sh.git` or `2cuGitHub:Cerulean-Circle-GmbH/once.sh.git`
   - Wrong: `git clone https://github.com/Cerulean-Circle-GmbH/once.sh.git`
2. **Install must also seed SSH keys** for the `2cuGitHub` host alias to work
   - SSH config alias `2cuGitHub` must point to `github.com` with the right `IdentityFile`
   - Keys must be present and readable by the container user
3. **Optional: better error message** — "no SSH keys configured" vs "couldn't connect" diagnosis would save debugging time

## Architect Design Review (2026-06-10)

**Recommendation: Option C — Volume mount, never bake keys**

- **Never** bake keys in image (security)
- **No** secret manager (over-engineering for this use case)
- **Volume mount** host SSH keys read-only: `docker run -v ~/.ssh:/root/.ssh:ro`

### Real bug: SEQUENCING

`oo install` currently:
1. Clones via HTTPS first
2. Sets up SSH after

Should be:
1. **Seed SSH config + verify key FIRST** (ossh already has `2cuGitHub` alias creation at line 556)
2. Run `git clone` via SSH
3. HTTPS only as fallback with WARNING

### Expert action

Reorder install to:
- SSH-first clone (using existing `2cuGitHub` alias from ossh)
- HTTPS-fallback-with-warning if SSH unavailable
- `ossh` config seeding runs BEFORE the clone, not after

## Expert Delivery (2026-06-10, commit 66212be on top of 0bdd8df)

**Architect refinement applied:**

1. When `ossh` is already on PATH, use `ossh config.create 2cuGitHub git@github.com:...` (canonical path — handles IdentityFile, auto-detects keys, idempotent)
2. Inline Host block only as bootstrap-edge fallback
3. Clone URL is `2cuGitHub:Cerulean-Circle-GmbH/once.sh.git` from the start (not `git@github.com:...`)
4. Cascade: `2cuGitHub:` → `git@github.com:` → HTTPS
5. Post-clone remote normalization only fires if remote isn't already `2cuGitHub:` form
