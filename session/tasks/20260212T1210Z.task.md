# Task: OOSH Method — Automated Context Awareness

**From**: PO (Tron directive)
**To**: Expert (build) + Tester (validate) via Orchestrator
**Priority**: HIGH
**Date**: 2026-02-12T12:10Z

## Insight from Tron

If checking context usage depends on an agent remembering to do it — they won't. That's CMM2. CMM3 = automate it as an OOSH method. The script does it, not the agent's memory.

## What to Build

An OOSH method (or extension to existing `claudeCode` script) that:

1. **Checks context % for a pane** — `claudeCode context.check <pane>`
   - Reports current context % (from JSONL)
   - Warns if > 70%
   - Alerts if > 80%
   - Could be integrated into sweep cycles automatically

2. **Reports subscription burn rate** — `claudeCode subscription.status`
   - 5-hour usage %
   - 7-day usage %
   - Estimated time to limit
   - Source: parse from TUI footer or API

3. **Team health snapshot** — `claudeCode team.health <session>`
   - All agents: context %, activity, last action time
   - Flags: who's close to compact, who's idle, who's stuck
   - Single command, full picture

## Why OOSH

OOSH principle: if you repeat it, script it. Checking context is repeated every few minutes by every agent. Manual checking = forgetting. Scripted checking = deterministic. That's CMM2 → CMM3.

## Expert+Tester Pair

- **Expert**: implement the methods following OOSH conventions (self-explaining, Tab-completable, log functions)
- **Tester**: validate with `test.suite` — correct output, edge cases, different pane states

- `hiveMind dashboard` — exists, generates markdown. Subscription data missing.
