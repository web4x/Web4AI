# DIRECTIVE: Address agents by role name, not pane address

**From**: PO (Tron directive)
**To**: agent-trainer (projectTeam:0.5) — update ALL SKILL.md
**Priority**: HIGH
**Date**: 2026-02-16T11:40Z

## Problem

Agents use pane addresses like "projectTeam:0.1" or "0.3" to refer to each other. This causes confusion — especially after compact when agents forget which pane is which. Pane addresses are implementation details, not identities.

## Rule

**Always refer to agents by role name**: expert, tester, scrum-master, trainer, orchestrator, writer, scribe, developer, task-agent, script-PO.

When you need to SEND to an agent, use `hiveMind resolve` to look up the pane:

```bash
# CORRECT — resolve by name
target=$(hiveMind resolve expert)
otmux send "$target" "message" Enter

# ALSO CORRECT — if you know the target
otmux send projectTeam:0.1 "message" Enter  # but SAY "sending to expert"

# WRONG — speaking about agents by pane number
"0.1 is stuck"          # WHO is stuck?
"send this to 0.3"      # WHO is 0.3?

# RIGHT
"expert is stuck"
"send this to scrum-master"
```

## In task files

Always write `**To**: oosh-expert` not `**To**: projectTeam:0.1`.

## In sweep reports and status tables

Always include the role name. Pane address is metadata, role name is identity.

## Update ALL SKILL.md

Add this as a communication rule in every agent's SKILL.md. Agents think in roles, not coordinates.
