## Problem

When tmux is shut down (reboot, crash, logout), all sessions, windows, panes, and agent assignments are lost. Rebuilding the team layout manually is tedious and error-prone.

## Solution

Persist the full session layout to a `~/config/otmux.<session>.scenario.env` file that can be sourced to recreate the exact layout.

### Save: `otmux tree.save <session>`

Capture the current state and write to `~/config/otmux.<session>.scenario.env`:

```bash
# ~/config/otmux.projectTeam.scenario.env
# Saved: 2026-02-16T11:45Z
OTMUX_SESSION=projectTeam
OTMUX_WINDOWS=2
OTMUX_W0_PANES=6
OTMUX_W0_LAYOUT="tiled"  # or the actual layout string
OTMUX_W0_P0_TITLE="orchestrator"
OTMUX_W0_P0_ROLE="orchestrator"
OTMUX_W0_P0_DIR="/Users/Shared/Workspaces/AI/Claude"
OTMUX_W0_P1_TITLE="oosh-expert"
OTMUX_W0_P1_ROLE="oosh-expert"
OTMUX_W0_P1_DIR="/Users/Shared/Workspaces/AI/Claude"
# ... all panes, all windows
OTMUX_W1_PANES=6
OTMUX_W1_P0_TITLE="woda-writer"
# etc.
```

The format follows the OOSH web4.scenario.env pattern — sourceable, persistent, in `~/config/`.

### Restore: `otmux tree.restore <session>`

1. Source `~/config/otmux.<session>.scenario.env`
2. Create the tmux session with correct number of windows and panes
3. Set pane titles from saved values
4. Set working directories
5. Register roles in hiveMind registry

This does NOT restart Claude agents — that's a separate bootstrap step. It recreates the empty tmux structure so agents can be booted into their correct panes.

### Auto-save

Consider auto-saving via `otmux tree.save` after every `hiveMind agent.bootstrap` or on a timer.

## Reference

- `otmux` already has pane/window management methods
- `hiveMind` registry has the role→pane mapping
- `~/config/` is the OOSH config pattern (persistent, sourceable)
- Look at how `session/setup-project-team.sh` currently creates the layout — that's the manual version of what this should automate
