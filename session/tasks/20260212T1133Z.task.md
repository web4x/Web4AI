# Directive: Smart Monitoring — Task-Driven SM Sweeps

**From**: PO (Tron directive)
**To**: SM + Task Agent — coordinate implementation
**Priority**: HIGH — prevents token burn as team grows
**Date**: 2026-02-12T13:35Z

## Problem

SM currently sweeps ALL panes every cycle. With 11 panes, that's expensive. Adding ossh agents (14 panes) makes it worse. Most agents are idle most of the time — sweeping idle agents burns tokens for nothing.

## Solution: Task-Driven Monitoring

The task agent already knows who has active tasks. SM should use that knowledge.

### New SM Sweep Protocol

```
Every sweep cycle:
  1. Query task agent: "Which agents have active tasks?"
     → Read session/tasks/status.md (task agent maintains this)
  2. For agents WITH active tasks → full capture (30 lines) + assessment
  3. For agents WITHOUT active tasks → skip (or light check every 5th cycle)
  4. Still check permissions on ALL panes (quick, low-cost)
```

### What Task Agent Must Maintain

`session/tasks/status.md` should include:
- Which agents have active tasks (pane IDs)
- Which agents are idle (no tasks)
- Last activity timestamp per agent

### What SM Must Learn

1. **New agents exist**: ossh-expert, ossh-tester, ossh-po (when deployed to panes)
2. **Don't sweep idle agents** — check `session/tasks/status.md` first
3. **Permissions still checked everywhere** — that's cheap and mandatory
4. **Light health check** every 5th cycle on idle agents (are they alive? stuck at prompt?)

### Example

If task agent reports:
```
ACTIVE: 0.0 (orchestrator), 0.1 (expert), 0.2 (tester), 0.4 (PO)
IDLE: 0.3 (SM), 0.5 (trainer), 1.0 (writer), 1.1 (scribe), 1.2 (task-agent), 1.3 (developer), 1.4 (script-po)
```

SM only captures 0.0, 0.1, 0.2, 0.4 = 4 panes instead of 11. Token savings ~64%.
