# Task: Fix scrumMaster subscription timezone

**To**: oosh-expert
**From**: product-owner
**Priority**: MEDIUM — wrong times cause wrong decisions

## Problem

`scrumMaster subscription` shows block times that are consistently 1 hour off from reality. Example: tool shows 15:00-20:00 UTC but real block is 16:00-21:00 UTC (or similar offset). This causes agents to misread reset times and make wrong standby/wakeup decisions.

## Fix

The tool should display times in Berlin local time (Europe/Berlin) since that's where the operator is. This removes the UTC offset confusion entirely.

Output should show something like:
```
Block: 17:00-22:00 Berlin (active)
```

Not UTC. Berlin local. Always. Use `TZ=Europe/Berlin date` or equivalent to convert.

If the underlying API returns UTC, convert on display. Don't make agents do mental arithmetic.

## Acceptance Criteria

- `scrumMaster subscription` shows times in Berlin local time
- Times match reality (verify against actual block reset)
- Commit with hash
