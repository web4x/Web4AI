## Root cause (measured)
`session/tools/lint-memory-index.mjs` exists and is correct (exit `1` on any hazard, line 120), but **nothing runs it**. Peer memory writes grew the index 24,203 → 24,924 B — past the 24,400 B auto-load limit — and the tail was silently dropped on every boot. The harness already emits an *advisory* size note on some Edits of MEMORY.md; it did not prevent the growth (advisory, Edit-only, and most memory writes here are Write or Bash).

## Proposed trigger (two layers)
1. **At write time — PostToolUse, matcher `Write|Edit|Bash`.** A small script reads the hook's stdin JSON; if `tool_input.file_path` (Write/Edit) or `tool_input.command` (Bash) touches `/root/.claude/projects/-var-dev-Workspaces-AI-Claude/memory/`, run `node session/tools/lint-memory-index.mjs`. On exit ≠ 0, print the lint output to **stderr and exit 2** → the writing agent sees RED immediately and fixes the index in the same turn. Otherwise exit 0 silently (no token cost on GREEN).
2. **At boot — SessionStart.** Run the same lint, report-only (non-blocking). Catches writes the path-match misses (other hosts, unusual Bash forms).

Sketch for `.claude/settings.json` (alongside the existing PreToolUse/PreCompact entries):
```json
"PostToolUse": [{ "matcher": "Write|Edit|Bash",
  "hooks": [{ "type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/memory-index-guard.py\"" }] }],
"SessionStart": [{ "matcher": "",
  "hooks": [{ "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/session/tools/lint-memory-index.mjs\"" }] }]
```

## Before wiring (gates)
