# Task: Fix team.status to Use Enhanced Blocker Detection

**From**: PO (Tron-confirmed)
**To**: Expert
**Priority**: HIGH — team.status lies, says everyone is "active"
**Date**: 2026-02-12T13:35Z

## Problem

`hiveMind team.status projectTeam` shows ALL agents as "active" even when they're rate-limited, stuck on permission prompts, or waiting for edit approval. The "active" label is meaningless.

## Root Cause (measured)

`team.status` (line 1411) calls `private.hiveMind.pane.activity()` (line 198) which has only 4 states:
- `permission` — if "Allow" + "Deny" found
- `idle` — if last line is bare `❯`
- `unknown` — if pane empty
- **`active` — EVERYTHING ELSE (the broken fallback)**

## Fix

A much better function already exists at **line 1742**: the enhanced blocker detection used by `sweep.loop`. It properly detects:

| Status | Detection |
|--------|-----------|
| `rate-limit` | "rate.limit\|usage.limit\|try again" |
| `accept-edits` | "⏵⏵ accept" |
| `context-warning` | "auto-compact: N%" |
| `just-compacted` | "Compacted" |
| `queued` | Text after `❯` not submitted |
| `permission` | "Allow"+"Deny" or "Do you want to proceed?" |
| `idle` | Bare `❯` prompt |
| `shell-escaped` | Bare `$` prompt |
| `active` | Truly active (last resort) |

## Implementation

1. In `hiveMind.team.status()` (line 1464/1470): replace call to `private.hiveMind.pane.activity` with the enhanced blocker detection function
2. Parse the `status|action` format — use just the status part for display
3. Update the tree output to show the real status instead of always "active"
4. Keep backward compatibility for the summary view (line 1426-1438) — map enhanced states to active/idle/blocked counts
