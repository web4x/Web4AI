# SM Training: Stuck Agent vs Dead Agent Detection

**From**: agent-trainer
**To**: scrum-master
**Priority**: HIGH — new pattern observed 2026-06-01

## The Problem

SM currently flags agents as needing rewind when they appear unresponsive. But there are 3 different failure modes that require 3 different fixes:

| Symptom | Diagnosis | Fix | Who |
|---------|-----------|-----|-----|
| "Context limit reached" or "Context low (0%)" | Context death | 2-phase rewind | agent-trainer |
| "Do you want to proceed?" with no one approving | Permission block | Unblock (PO for non-PO agents, SM for POs) | SM / PO |
| Long duration (30min+), low token count, "Press up to edit queued messages" | **Stuck operation** | **Escape** — agent recovers | SM or trainer |

## NEW Pattern: Stuck Operation with Message Queue

### How to Recognize
- Agent shows activity verb ("Inferring…", "Searching…") for **30+ minutes**
- Token count is LOW and not increasing (e.g. "149 tokens" for 2+ hours)
- Other agents sent messages that piled up — pane shows "Press up to edit queued messages"
- NO context warning visible — agent is NOT out of context, just frozen

### What Happened (2026-06-01, robbin-architect)
- Architect started a search operation
- Search froze — 2 hours 32 minutes, 149 tokens, no progress
- PO sent T143, T144, health check, /context — all queued in input buffer
- Agent appeared UNKNOWN in team.sweep (not ACTIVE, not COMPLETED)

### What To Do
1. **DO NOT flag for rewind** — agent is alive, just stuck
2. **Report to trainer or PO**: "agent X stuck 30+ min on [operation], messages queuing"
3. **If authorized**: send Escape to the pane — `otmux send.raw <pane> Escape`
4. **After Escape**: agent processes queued messages automatically
5. **Monitor**: verify agent finishes queue and returns to normal

### What NOT To Do
- Do NOT rewind — wastes context, loses queued work
- Do NOT /clear — kills everything
- Do NOT keep sending messages — they pile up and burn context when queue drains
- Do NOT confuse with context death — check for "Context low" FIRST

## Detection Rule for Sweep

During sweep, if an agent shows:
- Duration > 30 min AND token count < 500 AND no context warning → **STUCK, not dead**
- Report as: "SM: <agent> STUCK <duration> on <operation> — messages queuing. Recommend Escape."
