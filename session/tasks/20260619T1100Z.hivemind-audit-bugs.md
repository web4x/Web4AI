## Bugs Found in the Audit Tool

### Bug #1: Audit silently truncates output mid-iteration
**Symptom**: When run, the audit output stops at ~15 rows. For my system with 4 active sessions + 18+ panes, ooshTeam:0.2 through 0.5 are MISSING from output every run.
**Impact**: Real consistency issues on later panes are invisible.
**Repro**: `hiveMind consistency.audit` — output truncates regardless of where the truncation point falls.
**Suggested fix**: Find the stdout/file write buffering issue; could be log.level interaction, could be `head -N` somewhere, could be premature `return` in iteration. Compare row count to `otmux sessions` × pane.list to detect truncation.

### Bug #2: MATCH check tolerates `@MachineName` title suffix
**Symptom**: Pane title `scrum-master@MacStudio` was reported as ✓ vs registry `scrum-master` (those should be considered MISMATCH per Tron's example).
**Impact**: Real title drift hidden behind ✓ marks. Hides identity confusion (F-T3 root cause).
**Suggested fix**: Strict equality, OR explicit normalization with WARNING for stripped suffixes.
**Workaround applied**: Manually `otmux pane.lock` each pane to remove suffixes.

### Bug #3: Audit reports stale UUID from forks.env, not session.id live
**Symptom**: Post-fork, registry has new UUID in sessions.env but audit shows "UUID stale" because forks.env wasn't updated.
**Impact**: After `claudeCode fork`, audit reports false stale until forks.env manually appended.
**Suggested fix**: `claudeCode fork` should append to forks.env automatically. OR audit should prefer live `session.id` over forks.env.
**Workaround applied**: Manually appended fresh entries to `~/config/hivemind.forks.env`:
- `TRONinterface:0.1|scrum-master|dfcea556-c82a-4d45-a5c1-5792b6530ba2|live|`
- `TRONinterface:0.0|TRONinterface-agent|2267e3b0-315f-4297-8e93-3edbedc5d73e|live|`

### Bug #4: `tronMonitor switch` updates display but not registry
**Symptom**: After `tronMonitor switch ooshTeam`, the screen displays ooshTeam, but `~/config/hivemind.roles.env` still has `TRONinterface:0.3|TRON-Monitor:robbinTeam`.
**Impact**: Audit reports `title≠reg` permanently.
**Suggested fix**: `tronMonitor switch` should update the roles registry entry to match.
**Workaround applied**: `sed -i 's|TRON-Monitor:robbinTeam|TRON-Monitor:ooshTeam|'` on roles.env.

### Bug #5: `tronMonitor prune` keeps stale TRON-Monitor:<deadTeam> in roles
**Symptom**: After `tronMonitor prune` removed robbinTeam from monitor tracking, the roles entry `TRONinterface:0.3|TRON-Monitor:robbinTeam` remained.
**Impact**: Stale registry vs prune state.
**Suggested fix**: Prune should also reconcile roles registry for tronMonitor panes.
