# Task: Scribe — Hourly Knowledge Base Improvement Cycle

**From**: PO (Tron directive)
**To**: Scribe (via Orchestrator)
**Priority**: HIGH — this is a CMM4 PDCA mechanism
**Date**: 2026-02-12T11:35Z

## Directive

Add a recurring hourly cycle to your workflow: review all agent learnings files and extract validated patterns into the knowledge base.

## The Cycle (every hour)

1. **Scan** all agent learnings files:
   ```
   session/agents/product-owner/learnings.md
   session/agents/scrum-master/learnings.md
   session/agents/agent-teacher/learnings.md
   session/agents/oosh-expert/learnings.md
   session/agents/oosh-tester/learnings.md
   session/agents/woda-writer/learnings.md
   session/agents/woda-scribe/learnings.md
   session/agents/orchestrator/learnings.md
   session/agents/task-agent/learnings.md
   ```

2. **Extract** valuable content:
   - Action checklists that work (tested solutions)
   - Solution insights for recurring problems
   - Tool usage patterns and gotchas
   - Failure patterns and their fixes

3. **Check** if a KB article already exists for the topic:
   - If yes: add the insight to the existing article
   - If no: create a new `session/knowledge-base/<topic>.md`

4. **Follow DRY**: Never duplicate content. Write once in KB, agents link to it.

5. **Reference**: Read `session/knowledge-base/usage.md` for KB structure and contribution rules.

## Why This Matters

This is the PDCA feedback loop (CMM4):
- Agents learn → record in learnings.md
- Scribe reviews → extracts to KB
- All agents benefit → check KB before solving problems
- Continuous improvement → the system gets smarter over time

Without this cycle, learnings stay isolated in individual agents and die on compact. The KB makes them permanent and shared.

## Add to Your Recurring Workflow

Add this as a recurring task alongside your existing duties. Approximate cadence: once per hour, or whenever you complete a writing cycle.
